## Usage

<code>[LeanToTypeTheory]()[*env*, *name*]</code> imports the Lean constant *name* from the [LeanEnvironment]() *env*, with every constant it depends on, into a [TypeTheoryEnvironment](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/TypeTheoryEnvironment) of the [WolframInstitute/TypeTheory](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory) proof engine, whose own kernel checks each declaration again.

<code>[LeanToTypeTheory]()[*env*, {*name1*, *name2*, ...}]</code> imports several constants.

<code>[LeanToTypeTheory]()[*term*]</code> imports the constant of the [LeanTerm]() *term*.

## Details & Options

- TypeTheory is a Calculus of Inductive Constructions kernel written in the Wolfram Language. [LeanToTypeTheory]() gives the result of checking the import with it, independently of Lean's kernel: a [TypeTheoryEnvironment](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/TypeTheoryEnvironment), or a [Failure]() naming the Lean constant TypeTheory rejects.
- The constants are taken in dependency order. An inductive type comes with its constructors; its recursor `X.rec` is generated by TypeTheory as <code>[InductiveRecursor](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/InductiveRecursor)["X"]</code>, and then compared with Lean's: a recursor whose type differs gives a `"RecursorMismatch"` [Failure]().
- Lean names stay strings, so the imported theorem `"Nat.zero_add"` is the constant `"Nat.zero_add"` of the TypeTheory environment, and Lean's `Nat` becomes its natural numbers, so literals mean the same.
- Every term is imported as a core term of TypeTheory, with every argument and every universe level given, so nothing is filled in again on the TypeTheory side. A subterm that occurs many times, as in a proof that a tactic such as `omega` writes, is imported once and shared, as Lean shares it.
- The option `"Environment"` gives a [TypeTheoryEnvironment](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/TypeTheoryEnvironment) to import into; constants it already declares are not imported again.
- A block of mutually inductive types is imported as one declaration of all its types, and a type nested in a container, as Lean's syntax trees are in `Array`, as itself: TypeTheory checks the nesting as Lean's kernel does. Every recursor of the block, `X.rec_k` on a container included as <code>[InductiveRecursor](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/InductiveRecursor)["X", k]</code>, is compared with Lean's.
- A string literal is written as Lean's kernel reads it: `String.ofList` applied to the list of its characters, each `Char.ofNat` of its code point.
- The operations Lean's kernel computes on literals with GMP, `Nat.add`, `Nat.mul`, `Nat.pow`, `Nat.div`, `Nat.ble` and the others, are registered with TypeTheory as they are imported, so it computes them on literals with integers too, and a proof about numbers near 2^64 checks at once.
- Lean's kernel has the computation rule of its quotient types built in. The import adds it as the TypeTheory rewrite rules `"Quot.lift computes"` and `"Quot.ind computes"`, so a cone with quotients, such as that of `funext`, is imported under the rules of the calculus of inductive constructions with rewrite rules allowed, unless the option `"Environment"` gives an environment of other rules.
- The first call loads the paclet `WolframInstitute/TypeTheory`, which must be installed.

## Basic Examples

A Lean theorem, compiled from source:

```wl
lean = LeanImportString["theorem probe (n : Nat) : 0 + n = n := Nat.zero_add n"]
```

<!-- => LeanEnvironment summary box: 1 constant -->

Import `Eq.symm` with what it depends on:

```wl
env = LeanToTypeTheory[lean, "Eq.symm"]
```

<!-- => TypeTheoryEnvironment summary box: 5 constants -->

The constants TypeTheory checked:

```wl
Keys[env]
```

<!-- => {"Eq", "Eq.refl", InductiveRecursor["Eq"], "rfl", "Eq.symm"} -->

The imported theorem, read back in TypeTheory:

```wl
env["Eq.symm"]
```

<!-- => theorem Eq.symm : ∀_{α ∶ Sort u} ∀_{a ∶ α} ∀_{b ∶ α} Eq[a, b] ⇒ Eq[b, a] -->


```wl
Information[zeroAdd, "Kinds"]
```

```wl
TypeTheoryCheck[TypeTheoryTerm["Nat.zero_add", zeroAdd]]
```

```wl
TypeTheoryCheck[zeroAdd]
```

Two mutually inductive types, imported from Lean:

```wl
parity = LeanToTypeTheory[LeanImportString["mutual
inductive Even : Nat → Prop
  | zero : Even 0
  | succ {n : Nat} : Odd n → Even (n + 1)
inductive Odd : Nat → Prop
  | succ {n : Nat} : Even n → Odd (n + 1)
end"], "Even"]
```

<!-- => TypeTheoryEnvironment summary box: 40 constants -->

Mutually inductive types import together, each with its recursor:

```wl
Select[Keys[parity], Function[key, ! FreeQ[key, "Even" | "Odd"]]]
```
