## Usage

<code>[TypeTheoryToLean]()[*env*, *name*]</code> gives Lean 4 source declaring the constant *name* of the [TypeTheoryEnvironment](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory#ref/TypeTheoryEnvironment) *env*, with every constant it depends on that Lean does not have, for [LeanImportString]() to compile and Lean's kernel to check.

<code>[TypeTheoryToLean]()[*env*, {*name1*, *name2*, ...}]</code> gives the source for several constants.

## Details & Options

- The declarations are read back from the [WolframInstitute/TypeTheory](https://www.wolframcloud.com/obj/wolframinstitute/TypeTheory) environment exactly and written with every application explicit (`@f a b`) and every universe level given, so Lean fills in nothing.
- A constant that came from Lean, through [LeanToTypeTheory](), keeps its Lean name and is not declared again.
- TypeTheory's prelude constants that Lean has in `Init` are written as Lean's: `NonNegativeIntegers` is `Nat`, `Equal` is `Eq`, `And` is `And`, `Equivalent` is `Iff`, `Booleans` is `Bool`, and their constructors and recursors likewise; the Booleans' constants `"true"`, `"false"`, `"not"`, `"and"` and `"or"` are `Bool.true`, `Bool.false`, `Bool.not`, `Bool.and` and `Bool.or`, with the same definitions. `Plus` becomes `Nat.add`, which computes the same on constructors, so a proof that does not depend on how `Plus` is defined checks in Lean too.
- The prelude's axioms are Lean's: `PropositionalExtensionality` is `propext`, `FunctionExtensionality` is `funext` and `Choice` is `Classical.choice`, so a classical proof depends on Lean's own axioms and declares none.
- Every other constant is declared under the namespace `TypeTheory`, as an `axiom`, a `noncomputable def`, a `theorem` or an `inductive`, and an opaque definition, declared with `"Opaque" -> True`, as a `noncomputable opaque`; a block of mutually inductive types is written as Lean's `mutual` block.
- Compiling the source with [LeanImportString]() has Lean's kernel check every declaration, independently of TypeTheory's.
- Lean's kernel follows the calculus of inductive constructions, the rules of TypeTheory's prelude. An environment whose rules have no Prop, such as TypeTheory's HoTT environment, or that has rewrite rules other than the quotient rules [LeanToTypeTheory]() adds, which are Lean's own, gives `Failure["UnsupportedRules", ...]`.

## Basic Examples

Prove `0 + n == n` by induction in TypeTheory:

```wl
proof = TypeTheoryProof[ForAll[{Typed[n, NonNegativeIntegers]}, 0 + n == n], {
    TypeTheoryTactic["Introduce", n],
    TypeTheoryTactic["Induction", n],
    TypeTheoryTactic["Reflexivity"],
    TypeTheoryTactic["Introduce", k, ih],
    TypeTheoryTactic["Exact", EqualityCongruence[NaturalNumberSuccessor, ih]]
}]
```

<!-- => Proof complete -->

A theorem with that proof, added to the prelude:

```wl
proved = TypeTheoryEnvironment[{TypeTheoryTheorem[ZeroLeftIdentity, proof]}]
```

<!-- => TypeTheoryEnvironment summary box: 170 constants -->

Write the theorem as Lean source:

```wl
source = TypeTheoryToLean[proved, ZeroLeftIdentity]
```

<!-- => "-- Generated by LeanLink's TypeTheoryToLean: TypeTheory declarations, for Lean's kernel to check.\n\ntheorem TypeTheory.EqualityCongruence.{u, v} : ... :=\n  ...\n\ntheorem TypeTheory.ZeroLeftIdentity : ((n : @Nat) -> (@Eq.{1} @Nat (@Nat.add (0 : Nat) n) n)) :=\n  (@fun (n : @Nat) => (@Nat.rec.{0} ...))\n" -->

Lean compiles it, and its kernel accepts the proof:

```wl
leanEnv = LeanImportString[source]
```

<!-- => LeanEnvironment summary box: 2 constants -->

The theorem, as Lean states it:

```wl
leanEnv["TypeTheory.ZeroLeftIdentity"]["TypeForm"]
```

## Scope

A Lean theorem, compiled from source:

```wl
lean = LeanImportString["theorem probe (n : Nat) : 0 + n = n := Nat.zero_add n"]
```

<!-- => LeanEnvironment summary box: 1 constant -->

Lean's `Eq.symm`, imported into TypeTheory:

```wl
imported = LeanToTypeTheory[lean, "Eq.symm"]
```

<!-- => TypeTheoryEnvironment summary box: 5 constants -->

A constant imported from Lean keeps its name, so an imported environment exports nothing again:

```wl
TypeTheoryToLean[imported, "Eq.symm"]
```

<!-- => "-- Generated by LeanLink's TypeTheoryToLean: TypeTheory declarations, for Lean's kernel to check.\n" -->

---

The prelude proves the excluded middle from its axioms, which are Lean's, so Lean checks the proof with its own axioms:

```wl
classical = LeanImportString[TypeTheoryToLean[TypeTheoryEnvironment["Prelude"], ExcludedMiddle]]
```

<!-- => LeanEnvironment summary box: 6 constants -->

The theorem, as Lean states it:

```wl
classical["TypeTheory.ExcludedMiddle"]["TypeForm"]
```

<!-- => "∀ (p : Prop), p ∨ ¬p" -->

## Possible Issues

A constant the environment does not declare:

```wl
TypeTheoryToLean[TypeTheoryEnvironment[{TypeTheoryTheorem[TwoPlusTwo, 2 + 2 == 4, EqualityReflexivity[4]]}], NotAConstant]
```

<!-- => Failure["UnknownConstant", ...] -->

---

Lean's kernel does not follow the rules of TypeTheory's HoTT environment, which have no Prop:

```wl
TypeTheoryToLean[TypeTheoryEnvironment["HomotopyTypeTheory"], UniverseNotSet]
```

<!-- => Failure["UnsupportedRules", ...] -->
